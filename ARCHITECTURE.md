# Радар вирусных роликов — полная инструкция для передачи другому помощнику

*Актуально на 23.11.2026. Владелец: Дмитрий (все аккаунты и ключи принадлежат ему).*
*Документ для любой нейросети или разработчика, который продолжит работу с Радаром: прочитать целиком до первого изменения.*

---

## 1. Что это и зачем

Радар собирает вирусные ролики («выстрелы») из Instagram (плюс немного YouTube Shorts и TikTok) по нише здоровья и нутры, разбирает их ИИ и показывает на сайте. Цель: найти механики, хуки, темы и форматы, которые набирают просмотры, и использовать их в собственном контенте (ИИ-ведущий научно-популярных роликов про суставы → воронка → SS-оффер). Ролики не перезаливаются: изучается механика, а не копируется видео.

**Сайт:** https://radar.sandboxmonroe.com (вход по логину и паролю).
**Код:** GitHub `monroeadam74-hub/radar` (сейчас **публичный** — рекомендуется сделать приватным, см. раздел 12).

## 2. Как всё устроено (схема)

```
GitHub (код + секреты + запуски)
  ├─ radar.yml (GitHub Actions) ──► python main.py  ──► Apify (сбор рилсов)
  │       по расписанию и вручную                    ──► Gemini (разбор видео)
  │                                                  ──► Cloudflare D1 «radar-db» (база)
  ├─ deploy.yml (deploy-web) ──► Cloudflare Worker «radar» (сайт + API) ◄── D1
  └─ diag.yml ──► проверка ответов сайта (вход секретом APP_USERS)
```

- **Сборщик** — `main.py` (Python), запускается только в GitHub Actions. Пишет в D1 через Cloudflare API.
- **Сайт** — Cloudflare Worker: `worker/src/index.js` (API) + `worker/public/index.html` (весь интерфейс одним файлом). Выкатывается автоматически при каждом изменении папки `worker/` (workflow **deploy-web**).
- **База** — Cloudflare D1 `radar-db` (тариф Workers Paid $5/мес, до 10 ГБ).

Значения секретов не видны никому (даже владельцу). Нейросети ключи давать **не нужно** — запуски берут их из секретов сами.

## 6. Режимы сборщика (`radar.yml` → Run workflow → mode)

Поля запуска: `mode`, `wave` (сколько аккаунтов), `budget` (потолок трат Apify, $), `igtest` (список ников через запятую), `import_run`, `max_analyze`.

| Режим | Что делает | Стоит денег |
|---|---|---|
| **wave** | Массовый сбор: следующие N аккаунтов из `wave_list.json` → до 300 рилсов с каждого → выстрелы → разбор двумя моделями → хвосты прошлых дней со свежими ссылками → направления по подписи для «не выстрелов» → журнал. **По расписанию каждый день 08:05 UTC (11:05 МСК)** | Apify ~$0,001/рилс, Gemini 3.1 ~$0,0043/разбор |
| profiles | обновление «Моих профилей» (глубокий скан новых, свежие ролики старых) | да |
| full / analyze | старый поиск по ключам (YouTube/TikTok) и разбор | да |
| funnels | разбор воронок по ссылкам из шапок профилей | почти нет (Gemini) |
| enrich | **бесплатно** перечитывает прошлые оплаченные запуски Apify и дописывает репосты, лайки, шапку, время публикации | нет |
| directions | разметка направлений | Gemini |
| visuals | разметка «Ведущий» и «Визуальный приём» | Gemini |
| thumbs | обложки | мало |
| quota | проверка ключей Gemini (по одному короткому запросу) | ~0 |
| profcheck | проверка профилей по списку `igtest` | ~$0,0026/профиль |
| cmpmodels, formats, reltest, igtest | тесты и выгрузки | мало |
| medenrich, medsnow, lookalike, natsnow, nathash | исследования списков аккаунтов (снежный ком, похожие, хештеги) | да, с потолком `budget` |

**Результаты в логе:** Actions → запуск → job → шаг `python main.py`. Журнал волны — строка `ЖУРНАЛ ВОЛНЫ:` и блок между `WAVEJSON_BEGIN` и `WAVEJSON_END`. Артефакты GitHub из этой среды не скачиваются, поэтому данные печатаются в лог.

## 7. Логика выстрела и разбора

- **Выстрел (профили и волны):** просмотры ≥ 2× скользящей медианы автора (±15 соседних роликов, без роликов моложе 3 дней) и ≥ 100 000 просмотров. Остальные ролики профиля — статус `profile_rest` («Профили: не выстрел»), с цифрами, но без разбора видео.
- **Разбор видео (вариант Б):**
  - `gemini-3.1-flash-lite` на **платном** ключе разбирает **все** выстрелы (полная карточка);
  - `gemini-3.5-flash-lite` на **бесплатном** ключе переписывает **тексты** (хук, эмоция, почему сработало, как адаптировать, субтитры, текст на экране), ~300 в день, от самых сильных к слабым;
  - классификация (`direction`, `direction_extra`, `host`, `visuals`, `moderation_risk`) всегда от 3.1. Склейка — функция `merge_an`; в разборе поле `_m: {cls, txt}` показывает, какая модель что сделала.
- **Хвосты:** выстрелы без разбора и разборы без текстов 3.5 добираются в следующих запусках со свежими ссылками на видео (официальный сборщик Apify по прямым ссылкам, ~$0,0023/ролик), до 3 попыток.
- **Направления «не выстрелов»:** по подписи, платная 3.1, 30 подписей за запрос, пустые → «Другое».
- **Стоп по деньгам:** при конце предоплаты Gemini или при потолке `wave_paid_usd` (сейчас $45) 3.1 останавливается, остаток уходит в очередь. Ошибка Apify (например, неоплаченный счёт) останавливает хвост, но волна завершается и журнал пишется.

**Статусы роликов:** `analyzed` — разобран · `queued` — ждёт разбора · `profile_rest` — не выстрел · `skip_lang` — другой язык · `skip_topic` — не по теме.

## 9. Сайт

- Вкладки: **Ролики** (список, фильтры, карточка с плеером, разбор, субтитры, динамика, воронка автора), **Сводка** (время публикаций ET, хештеги, монтаж), **Профили**, **Настройки**, **Запуски**, **Доступ**.
- **Вход:** логины из секрета `APP_USERS` — главные администраторы; остальные пользователи заводятся на сайте во вкладке **«Доступ»** (видна только админам).
- **Роли:** пользователь — смотрит и размечает; админ — плюс запуски, настройки, добавление и удаление профилей, «Следить», «Доступ». Ограничения проверяются и на сервере.
- Список роликов грузится облегчённо (`/api/videos?scope=main`), «не выстрелы» — по запросу (`scope=rest`, топ-3000 по просмотрам), полный разбор — по клику (`/api/video?id=`).

## 11. ПРАВИЛА (обязательны для любого помощника)

1. **Деньги.** Никаких автопереключений на дорогие сборщики. Любое платное действие сверх согласованного — только после явного «да» владельца. Потолки трат (`budget`, `wave_budget`, `wave_paid_usd`) зашиты в запуски — не снимать.
2. **Ключи и пароли** — только в секретах GitHub. Никогда не просить их в чат, не печатать в лог, не класть в файлы репозитория.
3. **Email владельца** не передавать внешним сервисам без согласия.
4. **Не использовать куки и свои аккаунты** для сбора. Никакого клоакинга.
5. **Никаких фейковых «врачей» и фейковых отзывов** в контенте. ИИ-ведущий — без «Dr.», халата, обещаний лечения.
6. **Оплату и ввод карт** делает только владелец (Cloudflare, Google, Apify).
7. **Расписание** включено только для режима `wave`. Включать и выключать другие расписания — с согласия владельца.
8. **Повторный разбор старых выстрелов** не делать без решения владельца.
9. **Перед массовым запуском** — проба на 1–2 аккаунтах с маленьким `budget`.
10. **Не удалять данные** в базе без явного согласия.

## 12. Как перейти на другую нейросеть (пошагово)

**Шаг 1. Выбрать инструмент.** Для работы с кодом подходят: Cursor, GitHub Copilot (агент), OpenAI Codex, Claude Code, Gemini Code Assist и т.п. Главное — чтобы инструмент умел работать с GitHub-репозиторием.

**Шаг 2. Дать доступ к репозиторию.**
- Cursor / VS Code: клонировать `monroeadam74-hub/radar` и открыть папку.
- Codex / Copilot / другие облачные агенты: подключить GitHub-аккаунт в настройках инструмента и выбрать репозиторий `radar`.
- Живой разработчик: GitHub → репозиторий → Settings → Collaborators → Add people.

**Шаг 3. Первым сообщением дать нейросети этот документ** (он лежит в репозитории как `ARCHITECTURE.md`) и написать:

> Ты продолжаешь работу над моим сервисом «Радар». Прочитай ARCHITECTURE.md целиком и соблюдай раздел 11 «Правила» без исключений. Ключей и паролей я в чат не даю — они в секретах GitHub. Перед любым платным запуском спрашивай моё «да» и называй сумму. Сначала кратко перескажи, как устроен Радар, и какие у тебя вопросы.

**Шаг 4. Проверка, что всё понято.** Попросить нейросеть: (а) объяснить, что делает режим `wave`; (б) запустить бесплатную проверку `quota`; (в) прочитать лог последнего запуска. Если путается — вернуть к документу.

**Шаг 5. Как нейросеть вносит изменения.**
- Меняет код → отправляет в ветку `main` (или через pull request, если владелец хочет проверять).
- Изменения в `worker/` выкатываются на сайт сами (deploy-web) за ~1 минуту.
- Изменения в `main.py` действуют со следующего запуска сборщика.
- Запуски — через GitHub Actions (вручную или CLI `gh workflow run radar.yml -f mode=...`).

**Шаг 6. Для аналитики без кода** (ChatGPT, Gemini и т.п.): завести нейросети или себе пользователя во вкладке «Доступ» и смотреть сайт, либо выгрузить данные (Cloudflare → D1 → Console → SQL-запрос → экспорт).

**Шаг 7. Сделать репозиторий приватным (рекомендуется).** Сейчас код, списки аккаунтов и **логи запусков** видны всем. Settings → General → Danger Zone → Change visibility → Private. Учесть: у приватного репозитория бесплатные минуты GitHub Actions ограничены (ориентир ~2 000 мин/мес на бесплатном плане; волна занимает ~1,5–2 ч в день, сверх лимита — платно, порядка $0,008/мин; актуальные условия проверить на github.com/pricing перед переключением). После окончания массового сбора запусков станет меньше.

## 14. Известные ограничения и планы

- Видео Instagram в карточке не грузится у части роликов: автор запретил встраивание или в ролике лицензированная музыка. Это не баг.
- «Не выстрелы» без поиска подгружаются топ-3 000 по просмотрам — нужен фильтр направления на сервере (план).
- Идея «выстрел внутри темы» для суставов (ролик сильнее медианы своей темы у автора) — план после данных.
- Пилот сбора постов и каруселей Instagram — после завершения рилсов (~после 25.11), ~$3–5.
- Посты/карусели, комментарии — пока не собираются.
- Предложения авторов от обычных пользователей («Предложить автора» с одобрением админа) — идея, не сделано.
